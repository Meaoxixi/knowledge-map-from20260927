同期工作大概有这些。大家共享的架构设计是说通过将整体架构变为3D vae 和 DIT这种基于transformer模块搭建起来的去噪网络，这一时期的生成画面质量迎来飞跃。当时的典型模型架构中的模块设计以双向注意力为主，主张在于所有的画面帧共享噪声，能够强化联合建模和时序一致性。这导致了两个比较严重的问题，也是后续时间模型生成转向因果流式生成的重要原因
1是因果性无法保证；2是延迟高
从训练范式的角度，模型学的是整段视频所有画面帧的联合分布P（x，T），模型没有见过“历史干净、未来带噪”的状态，所以无法以过去为条件往后续写；另外在模块层面双向的sptial attention没有因果mask的设计，联合去噪的设计会导致未来帧参与当前帧的去噪，所以因果性根本无法保证。
延迟高很好理解， 原生 video DIT沿用的full sequence diffusion的整段同步去噪方式，所以慢。

P4
所以2024 年底至 2026 年视频生成模型的探索重点 进入 因果流式生成 的探索工作，那说到因果性，语言生成的范式提供了一个很好的模板，chatgpt刚好在2023年爆火，其中的decoder-only transformer的设计本质是自回归建模，语言序列天然符合因果逻辑，LLM那边叫做 teacher forcing，训练目标是next-token prediction： p(x₁…x_T) = ∏ p(xₜ | x_<t)，像这样：
输入是：x1，x2，…… x{T-1}
目标是：x2，x3，……x{T}
logits = model(x[:, :-1])          # 输入：去掉最后一位 
loss   = cross_entropy(logits, x[:, 1:])  # 标签：去掉第一位
由于因果mask的存在使得位置 t 的注意力被限制在 ≤ t 的 token 上，看不到未来。于是 “一次前向算全序列” 和 “每个位置只看合法历史” 同时成立，而且这种方式在训练的时候不用串行，之前串行是指 第 t 步的输入 需要基于 模型第 t-1 步的输出，所以以往必须先跑完 t-1，拿到预测结果t，才能叠加输入的x0继续预测最后第 t 步，生成逻辑是按照时间串行展开的。而现在teacher forcing的做法时，喂进xt的条件的是来自GT的真实的x{t-1},所以任意时刻位置t的前置条件在训练时都全部已知 → 没有跨步运行时依赖 → 因此可以整段并行前向，这解决了之前慢的问题；另外因为喂的数据基于因果mask每个位置拟合的都是定义干净的 p(x_t | x_<t)，所以因果性建模能力得到提升；
但是teacher forcing的在于代价是训练时模型见过的样本由于始终来自GT，所以历史永远完美；而推理时没有GT了，模型只能基于自己上一次自己的生成的内容持续预测，其实给自己生成的样本赋予了过高的参考权重，导致误差会沿采样链累积 —— 所以 teacher forcing为提速和因果性生成能力的提高提供了一个很好的示范但是无法直接搬到视频生成架构中使用。
P5
于是针对teacher forcing存在的生成视频不稳定，容易累计误差的问题 Diffusion Forcing（Chen et al., NeurIPS 2024，Diffusion Forcing: Next-token Prediction Meets Full-Sequence Diffusion）这个时候就出现了【Diffusion forcing = Diffusion model + teacher forcing】，它给出的解决方案是在时间维度上解耦不同 Token 的噪声进度，具体看论文图所示，在训练阶段Diffusion Forcing 不为整段视频共用一个扩散时间步，而是为每一帧独立采样各自的噪声进度 $$\tau_t$$，再把对应帧前向扩散到该噪声水平。
[图片]
具体而言，在训练阶段，整个模型从整体上看是一个序列扩散模型，但是内部的结果是一个因果序列的RNN网络的感觉，以此实现因果约束。比如对第一行的图像帧序列而言，此时模型看到的是一组符合 “噪声进度沿时间轴呈现递进关系的” 的帧序列，它们的历史帧既可以是干净的真值，也可以处于任意加噪状态的情况
这样设计带来两点直接的改变。第一是缓解训练 — 推理分布不一致：teacher forcing 下模型见到的历史永远是干净真值，而推理时吃的是自己生成的、带有误差的历史；Diffusion Forcing 在训练中就覆盖了 “历史完全干净 → 历史部分加噪 → 历史接近全噪” 的各种状态，让模型对不完美、带噪的历史提前具备鲁棒性。
第二是它既可以像自回归那样逐帧、逐块因果地向前推演，保持帧间的连续，也可以在一个 chunk 内部对多帧做联合去噪维持整体一致性。
采样的时候，和扩散模型一样，需要有一个schedule，从一个白噪声开始，噪声强度逐渐降低到0。去噪过程迭代计算的顺序就是，从上到下，从左到右。
直觉上我认为可以这么理解，因为每个token的噪声水平独立，然后去噪预测的特征又具有链路上的因果结构；所以给每个token赋予不同噪声水平的操作感觉上是施加了不同程度的mask掩码，这种情况下，模型必须被迫学会建模任意的子序列的联合分布

P7
Diffusion Forcing 借鉴teacher forcing，相较于 full-sequence diffusion的联合建模方式实现了因果生成、输出变长预测的效果。但其本质上仍是 “以GT作为历史帧当条件” 的扩散模型。因为teacher forcing 是直接拿GT当条件参考；而Diffusion Forcing是把GT加了不同程度的噪声当历史帧去参考，所以底子还是基于GT的线性变化，这两种方式没有做到的是，训练过程中，模型始终不知道自己上一步预测出来的隐向量是什么样的，所以模型对于有偏估计的自我矫正能力无法习得，因为再怎么叠加组合的简单的高斯噪声不能模拟连续的有偏估计。所以Diffusion forcing存在的问题是如果推理阶段生成的帧有偏差，这个偏差恰好落在训练分布没有覆盖的区域里，这个条件有偏误差无法被矫正会持续累积。因此Self-Forcing（NeurIPS 2025 (Spotlight)）就主张补上这一块缺失，直接用预测的帧作为条件来预测下一帧噪声
[图片]
P7
以此来解决曝光偏差（exposure bias）问题——即模型在训练时基于真实（ground-truth）上下文进行学习，但在推理时却必须基于自身生成的不完美输出来生成后续序列
这里可以看到三者的对比:
1. Teacher Forcing：使用干净的GT图像作为条件来预测当前帧噪音
2. Diffusion Forcing：使用前面的带噪音图像作为条件来预测当前帧噪音，并且独立加噪音
3. Self Forcing：用预测的帧作为条件来预测下一帧噪音，在训练阶段就模拟推理时的完整流程
[图片]
它在算法上的优化还在于引入了KV缓存机制。模型在生成视频块时会缓存关键的键值对信息，这样在生成后续帧时可以直接复用这些缓存，大幅提升效率。
具体来说方法的话，Self Forcing 的训练和推理都围绕同一个核心：用一个因果扩散 Transformer作为底座，然后将模型自己生成的历史帧的 key/value 键值对可以像语言模型一样缓存下来，生成后续帧时直接复用、不必重算，长视频推演的效率由此可以得到保证。
我们可以来看训练单次step的数据流，先采样序列长度 N、去噪步数 T，以及随机截断点 s。
每一帧从纯噪声开始，沿去噪步数向前推进：只有到第 s 步才打开梯度，更新模型。

预测出干净 latent，收集进整条生成视频 Xθ；随后从这一帧提取 KV 嵌入、追加进缓存；其余去噪步都切断梯度，只负责注入更低噪声、推进采样。在这一步上，模型把当前帧预测成干净的画面特征，攒进整条生成视频里，同时把这一帧的缓存信息存下来，给后面的帧用。剩下的去噪步骤都不算梯度，只负责把噪声再降一点、接着往下推。
最后损失也不再逐帧计算 MSE，而是直接对齐生成分布和真实分布。也就是说拿整条生成视频去和真实视频做整体对齐 —— 保证模型生成出来的成片，在整体风格和运动规律上和真实视频是一个路子。
这里有两个工程上的取舍值得学习吧。第一，每帧只走大约 4 步去噪就出结果，精度够用；这样模型自己一步步展开训练时才跑得动，推理出来也快。第二，存进缓存的历史帧，梯度是切断的，不让它往回传。如果不切断，梯度会顺着模型自己生成的整条链一路倒传，显存很快就被撑爆。
采样序列长度 N，去噪步数 T，随机采样 s ∈ {1..T}
初始化 Xθ = []，KV = []
for i = 1..N:
    x_i^{t_T} ~ N(0, I)                       # 当前帧从纯噪声开始
    for j = T..s:
        if j == s:                            # 只有最后一步开梯度
            grad ON
            x̂_i^0 = Gθ(x_i^{t_j}; t_j, KV)   # 因果 DiT 预测干净帧
            Xθ.append(x̂_i^0)                 # 收集完整生成视频
            grad OFF
            kvi = GKVθ(x̂_i^0; 0, KV)         # 从输出帧提取 KV 嵌入
            KV.append(kvi)                    # 缓存为未来帧的条件
        else:                                 # 其他去噪步不开梯度
            grad OFF
            x̂_i^0 = Gθ(x_i^{t_j}; t_j, KV)
            sample ε ~ N(0, I)
            x_i^{t_{j-1}} = Ψ(x̂_i^0, ε, t_{j-1})   # 注入更低噪声
对 Xθ 计算视频级分布匹配损失，更新 θ
到了推理阶段，缓存有固定大小 L：新帧进来，就把最旧的那一帧缓存挤出去。训练时也会故意让当前块看不到第一块，提前演练这种 “旧缓存被挤掉” 的情况，这样长视频跑起来不容易出现画面闪烁。
推理数据流（rolling KV cache）示意图如下
给定要生成帧数 M，缓存长度为 L
初始化 KV = []
for i = 1..M:
    x_i^{t_T} ~ N(0, I)
    for j = T..1:
        x̂_i^0 = Gθ(x_i^{t_j}; t_j, KV)
        if j == 1:                       # 最终干净输出
            Xθ.append(x̂_i^0)
            kvi = GKVθ(x̂_i^0; 0, KV)
            if |KV| == L: KV.pop(0)      # 移除最旧帧缓存
            KV.append(kvi)
        else:
            sample ε ~ N(0, I)
            x_i^{t_{j-1}} = Ψ(x̂_i^0, ε, t_{j-1})
核心组件拆解如下：
- Gθ（因果 DiT）：在因果 3D VAE 的潜在空间工作。输入当前帧/块的噪声 token 与过去帧的 KV 嵌入，输出预测干净 latent；GKVθ 额外返回当前输出帧的 KV 嵌入。注意力是因果的，因此可像语言模型一样缓存。
- KV 缓存：保存自生成历史帧的 clean key/value。训练时把流入缓存的历史帧梯度切断（detach），避免反向传播穿过整个 rollout 导致显存爆炸；推理时用滚动缓存支持长视频外推。
- 少步扩散：用 4 步去噪近似每帧条件分布 pθ(xi|x<i)。这使自展开训练可行，同时也带来低推理延迟。
- 随机梯度截断（stochastic gradient truncation）：每个训练序列随机采样 s 作为最终输出去噪步，只对第 s 步启用梯度，其余步不记录梯度。这样所有中间去噪步都有机会接收监督，同时内存可控。
- 视频级整体分布匹配损失：不再逐帧计算 MSE，而是把整条生成视频 Xθ 送入 DMD、SiD 或 GAN 目标，直接拉近生成视频分布 pθ(x1:N) 与真实视频分布 pdata(x1:N)。
- 首帧注意力限制：训练时让模型在去噪当前块时不能看到第一块，以模拟滚动缓存逐出首个 latent 后推理分布，减少 flicker 伪影。

P8
到现在快速训练+因果生成的探索还在继续，self forcing解决了训练和推理分布的gap，但是没解决的遗留问题是：用在自生成历史对齐分布，理论有缺陷、成本高
[图片]
要聊Causal Forcing的出现和这三种forcing的对比之前必须要聊CausVid（2025CVPR），这个工作CausVid 的主要贡献是训练范式上的，从之前从零预训练或者后训练微调，转向“教师引导、学生继承”的蒸馏架构，我们提到过因果流式生成之前是原生Video DIT架构，当时的双向扩散模型能够实现很好的画面生成效果，但是受限于延迟高必须整段去噪，注意力交互上不满足因果关系。因此蒸馏架构主张：保留一个成熟的双向DIT模型作为教师，另训练一个轻量的自回归架构的因果学生模型，通过初始化和分布匹配把教师的生成能力迁移过来，然后学生模型的自回归架构又能满足因果生成的天性。
CausVid 就是这一蒸馏范式下的代表性方法，典型路径分四步：
1. Bidirectional teacher（双向教师）：取已有的双向预训练视频扩散模型作为教师；
2. ODE initialization（轨迹初始化）：用教师的生成轨迹对学生做 ODE 初始化，让学生一开始就落在接近教师的起点上，避免冷启动；初期以简单的 MSE 回归损失对齐教师输出；
3. Few-step causal AR student（少步因果学生）：学生是因果自回归扩散模型，注意力严格只看前文，可以逐帧、逐块滚动生成；同时用少步去噪近似条件分布，兼顾推理速度和流式能力；
4. Asymmetric DMD（不对称分布匹配）：进一步拉近学生生成分布与教师 / 真实分布，提升画质。
[图片]
但 CausVid 的 DMD 阶段，训练时喂给学生的历史前缀（prefix）仍然来自 ground-truth 或教师；而到了部署阶段，前缀只能来自学生自己生成的内容。两者来源不同，分布并不一致：学生可能只学会了在 “干净历史” 上生成下一段，却没有充分学会在 “自己生成的不完美历史” 上继续滚动。一旦推理中某步出错，后续条件就偏离训练分布，误差会沿链累积。
这个缺口正好引出后续两条改进路线：一是把训练历史换成学生自己的 rollout（Self Forcing），二是把监督教师换成与学生同构的因果教师（Causal Forcing）。
而如果我们把之前的self forcing应用到这个蒸馏架构上需要做的，是要拿一个双向教师去跑轨迹、给学生做初始化，还要存额外数据。所以成本高。
此外在理论上，双向教师预测某帧时能看到未来，学生部署时只看前文 —— 教师给的监督信号在因果模型上是不成立的，所以面向蒸馏架构的Self Forcing存在理论缺陷

阶段三：Self Forcing——解决训练与推理之间的分布差异
重点讲解
这一部分我建议作为整个第三阶段的核心。
首先回顾 CausVid：
它已经实现了因果生成、KV Cache 和少步蒸馏，但训练过程仍然存在一个值得关注的问题：
训练时使用真实历史帧，推理时使用模型自己生成的历史帧。
这会造成 Exposure Bias，也就是训练和推理的上下文分布不一致。
引入 Self Forcing。
它的核心思想可以用一句话概括：
训练时就让模型自己生成历史，再用自己生成的历史预测未来。
具体过程：
1. 输入初始条件。
2. 模型通过自回归 Rollout 生成视频。
3. 后续视频块以之前生成的内容作为条件。
4. 使用 KV Cache 保留历史信息。
5. 在模型自身生成的完整视频上计算视频级别的监督损失。

阶段四：Causal Forcing 与 Causal Forcing++——从能生成到正确地蒸馏
Causal Forcing++ 重点讲解
这一部分是我认为最值得深入讲解的技术迭代。
因为它不仅是在原有方案上提高性能，还重新审视了前面蒸馏过程中的理论问题。
4.1 Causal Forcing：教师与学生的架构必须匹配
先提出问题：
Self Forcing 虽然通过 Self-Rollout 解决了训练和推理之间的分布差异，但在初始化阶段，仍然存在一个值得注意的问题：
能否直接使用双向教师的 ODE 轨迹来初始化因果学生？
Causal Forcing 指出，这里面存在理论上的问题。
双向模型与因果模型具有不同的条件依赖结构。双向教师的概率流 ODE（PF-ODE）不一定能够为因果学生提供正确的逐帧映射监督。
因此，它先将双向基础模型微调为自回归模型，再使用这个因果教师进行 ODE 初始化，最后再进行 DMD 训练。
可以将其理解为：
- CausVid：使用双向教师帮助因果学生完成蒸馏。
- Self Forcing：让训练上下文更接近真实推理上下文。
- Causal Forcing：进一步保证蒸馏初始化阶段的教师与学生具有一致的因果结构。

4.2 Causal Forcing++：进一步解决少步生成的初始化问题
Paper page - Causal Forcing++: Scalable Few-Step Autoregressive Diffusion Distillation for Real-Time Interactive Video Generation
huggingface.co
这里重点讲：
Causal Forcing 已经改善了因果模型的蒸馏初始化，但它的 ODE 数据构造和初始化过程仍然存在一定计算成本。
当我们希望将生成步数进一步降低到 1～2 步，问题会变得更加明显。
Causal Forcing++ 提出了 Causal Consistency Distillation（因果一致性蒸馏）。
核心思想是：
不再依赖预先构建完整的 ODE 轨迹数据，而是通过相邻时间步之间的在线教师 ODE 监督，学习相同的自回归条件 Flow Map。
因此，它在少步初始化方面更加高效。
值得强调的结果包括：
- 从 Chunk-wise 4-step 进一步推进到 Frame-wise 1～2-step。
- Stage 2 训练成本降低约 4 倍。
- 首帧延迟降低约 50%。
- 进一步扩展到 Action-conditioned World Model。

CausVid 解决了如何把双向视频扩散模型变成因果生成模型的问题；Self Forcing 解决了模型训练时如何面对自己生成的历史的问题；Causal Forcing 解决了因果结构不匹配导致的蒸馏初始化问题；Causal Forcing++ 则进一步解决了如何高效地将因果生成模型推向极少步生成的问题。
阶段五：Self Forcing++——从短视频生成到长时序稳定性
重点讲解
这里我建议你不要把 Self Forcing++ 简单讲成 Self Forcing 的速度优化版。
它解决的是另一个问题：
即使模型已经能够按照自己的历史进行自回归生成，为什么视频长度不断增加时，质量还是会下降？
Self Forcing 的训练通常仍然受到教师模型生成长度的限制。当学生模型需要生成超出教师训练视野的长视频时，连续潜空间中的误差可能不断累积。
Self Forcing++ 的关键思路是：
利用学生模型自己生成的长视频，从中采样不同时间位置的片段，再使用短时域双向教师提供监督。

2. 如何避免长序列中的误差累积？ 从长视频中抽取不同位置的片段，利用教师的局部生成能力进行修正。
